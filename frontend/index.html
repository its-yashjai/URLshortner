The 3-replica Nginx setup is fully built and verified for correct round-robin and Snowflake ID uniqueness across workers — but this build environment runs on a single CPU core, where adding replicas adds scheduling overhead without adding compute, so it doesn't demonstrate a throughput gain here. It's written to scale on real multi-core hardware. Full methodology in docs/scale-report.md.

How a request actually moves

Nginx

Round-robins across 3 stateless replicas, marks one unhealthy after 3 failed attempts.

FastAPI replicas

Each holds its own Snowflake ID generator, seeded with a unique worker ID — no shared counter to lock.

Redis

Cache-aside for reads, write-behind buffer for click counts, flushed to Postgres every 2 seconds.

Postgres

Source of truth for URL mappings and click counts, guarded by an advisory lock on schema creation.
